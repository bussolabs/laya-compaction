# laya-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Laya judged no longer
needed. `hooks/laya.ts` is a thin adapter: it reads the plugin options, finds
the Laya server (if any), hands `session.compact` transcripts to the
`laya-compaction` library in `src/` (the plugin folder is the repository root,
so the hook imports it directly) and maps the result back onto session
messages. User and assistant text is never touched. How the state and the
questions are built is described in the root README.

The adapter talks to a `laya-serve` server in one of two ways:

- **Remote**, when `url` (option) or `LAYA_URL` is set: `POST
  $LAYA_URL/v1/systemone` through `$.http.fetch`, with
  `Authorization: Bearer $LAYA_API_KEY` when a key is set and `model` only
  when one is set.
- **Local**, otherwise: the shared server on `127.0.0.1:$LAYA_LOCAL_PORT`
  (default 8765), asked for `multilingual`. The hook probes `GET /health`; when
  nothing answers it runs a `sh` script through `$.process.run` that starts
  `uv tool run --from "laya[serve]==0.4.0" python serve/laya_serve.py` with
  `nohup … &` (output to `~/.cache/laya-local/serve.log`, a lock file against
  double starts) and returns at once, then polls health with `$.clock.sleep`
  for up to 10 minutes (the first start downloads the model). `LAYA_MODEL_DIR`
  makes it serve a fine-tuned checkpoint. Without `uv` the hook falls back.

The hook leaves a subagent's or fork's transcript to Claude Code, skips
`precompute` dispatches, adds the text typed after `/compact` to Laya's goal,
and returns kept assistant messages and tool results without their engine
`handle` (so the compaction survives `--resume`); plain user prompts keep it,
with their pasted images and documents. Auto-compaction runs only after an answered main-loop
turn. Display failures never change the outcome.

Every request sends `max_len` (`maxLen`, default 4096), and the hook falls
back when the server reports that it had to truncate the state.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export LAYA_URL="https://laya.example.com"   # omit for local mode (needs uv)

claude plugin marketplace add bussolabs/laya-compaction
claude plugin install laya-compaction@laya-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `url` | `LAYA_URL` |
| `apiKey` (sensitive) | `LAYA_API_KEY` |
| `model` | `LAYA_MODEL`, else omitted (local: `multilingual`) |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `maxLen` | `4096` |
| `maxStateTokens` | `maxLen − 112` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |

`url`, `apiKey` and `model`, and the local-only `LAYA_LOCAL_PORT` and
`LAYA_MODEL_DIR`, fall back to the process environment and then to the `env`
block of the settings files. `maxLen` trades speed for context (see the root
README).

Every option except `url`, `apiKey`, `model`, `compactAtPercent` and
`minReductionRatio` is passed straight to the library.
If Laya fails, the local server cannot be started, the response is malformed
or computed on a truncated state, the history cannot be fitted into the state
budget, or the estimated reduction is below `minReductionRatio`, the hook
logs a fallback and delegates to Claude Code's built-in compaction. The outcome
is shown as a toast and logged with the reduction, per-reason counts, state
size and request count; a per-call `decisions:` line with both probabilities is
logged for diagnosis. The `turn.complete` hook requests compaction when
`context.percent` reaches `compactAtPercent`, with an in-flight guard.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade. `$.process.run` is CLI-only, so local mode does not work
where the engine offers no process runner. That the server started by
`$.process.run` survives the hook was checked with the same script from Node,
not inside a Claude Code session.
